도구를 늘리면 시작은 빨라 보여도, 장애 시 복구 시간은 길어집니다.
최근 OpenStack 복구 작업에서 이 원칙을 다시 확인했습니다.

## 최소 도구 운영 원칙

- 새 도구는 **기존 명령 체계로 설명 가능할 때만** 도입합니다.
- 장애 대응은 "진단 → 복구 → 재검증" 3단계를 고정합니다.
- 팀원이 10분 안에 따라 하기 어렵다면 문서를 다시 씁니다.

## 실제 복구 루프

1. 서비스 상태 확인 (`compute service`, `network agent`)
2. 컨테이너/로그 확인 (`docker ps`, `docker logs`)
3. 1차 복구(재시작), 2차 복구(Kolla 재구성)
4. 테스트 인스턴스로 재검증 후 정리

## 문서화 기준

- 원인과 증상을 분리해 기록합니다.
- 실행 명령은 순서를 보존합니다.
- 재현 확인 기준(`ACTIVE`, agent `up`)을 함께 남깁니다.

도구의 수보다 중요한 것은 **복구 가능한 구조로 남겼는가**입니다.
