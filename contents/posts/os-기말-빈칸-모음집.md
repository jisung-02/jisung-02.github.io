# 9장: Memory Management
**1. Memory is central to the operation of a modern computer system and consists of a large array of bytes, each with its own address.**

- 메모리는 현대 컴퓨터 시스템의 운영에서 중심적인 요소이며, 각자의 주소를 가진 바이트 단위로 이루어진 큰 배열로 구성된다.
**2. One way to allocate an address space to each process is through the use of base and limit registers. The base register holds the smallest legal physical memory address, and the limit specifies the size of the range.**

- 각 프로세스에 주소 공간을 할당하는 한 가지 방법은 기본(base) 레지스터와 한계(limit) 레지스터를 사용하는 것이다. 기본 레지스터는 허용되는 가장 작은 물리적 메모리 주소를 담고, 한계는 해당 범위의 크기를 지정한다.
**3. Binding symbolic address references to actual physical addresses may occur during (1) compile, (2) load, or (3) execution time.**

- 심볼릭 주소를 실제 물리적 주소로 바인딩하는 작업은 (1) 컴파일 시점, (2) 로드 시점, 또는 (3) 실행 시점 중 어느 때나 발생할 수 있다.
**4. An address generated by the CPU is known as a logical address, which the memory management unit (MMU) translates to a physical address in memory.**

- CPU가 생성하는 주소를 논리 주소라고 하며, 메모리 관리 장치(MMU)는 이 논리 주소를 물리 메모리의 물리 주소로 변환한다.
**5. One approach to allocating memory is to allocate partitions of contiguous memory of varying sizes. These partitions may be allocated based on three possible strategies: (1) first fit, (2) best fit, and (3) worst fit.**

- 메모리를 할당하는 한 가지 방식은 연속적인 메모리 공간을 서로 다른 크기의 파티션으로 나누어 할당하는 것이다. 이 파티션 할당 시에는 (1) 첫 번째 맞춤, (2) 최적 맞춤, (3) 최악 맞춤 전략 중 하나를 사용할 수 있다.
**6. Modern operating systems use paging to manage memory. In this process, physical memory is divided into fixed-sized blocks called frames and logical memory into blocks of the same size called pages.**

- 현대 운영체제는 페이징을 사용하여 메모리를 관리한다. 이 과정에서 물리 메모리는 프레임(frame)이라 불리는 고정 크기의 블록으로 나누어지고, 논리 메모리는 동일한 크기의 블록인 페이지(page)로 나누어진다.
**7. When paging is used, a logical address is divided into two parts: a page number and a page offset. The page number serves as an index into a per-process page table that contains the frame in physical memory that holds the page. The offset is the specific location in the frame being referenced.**

- 페이징을 사용할 때 논리 주소는 페이지 번호와 페이지 오프셋의 두 부분으로 나뉜다. 페이지 번호는 프로세스별 페이지 테이블에서 해당 페이지를 담고 있는 물리 메모리 프레임을 찾기 위한 인덱스로 사용되며, 오프셋은 해당 프레임 내에서 참조하는 특정 위치를 의미한다.
**8. A translation look-aside buffer (TLB) is a hardware cache of the page table. Each TLB entry contains a page number and its corresponding frame.**

- 변환 조회 버퍼(TLB)는 페이지 테이블의 하드웨어 캐시이다. 각 TLB 엔트리는 페이지 번호와 해당 페이지를 담고 있는 프레임을 포함한다.
**9. Using a TLB in address translation for paging systems involves obtaining the page number from the logical address and checking if the frame for the page is in the TLB. If it is, the frame is obtained from the TLB. If the frame is not present in the TLB, it must be retrieved from the page table.**

- 페이징 시스템에서 주소 변환 시 TLB를 사용하는 절차는 논리 주소에서 페이지 번호를 얻은 후 해당 페이지에 대한 프레임이 TLB에 있는지를 확인하는 것이다. 만약 TLB에 있으면 해당 프레임을 바로 얻을 수 있고, TLB에 없으면 페이지 테이블에서 프레임 정보를 가져와야 한다.
**10. Hierarchical paging involves dividing a logical address into multiple parts, each referring to different levels of page tables. As addresses expand beyond 32 bits, the number of hierarchical levels may become large. Two strategies that address this problem are hashed page tables and inverted page tables.**

- 계층적 페이징은 논리 주소를 여러 부분으로 나누어 각 부분이 다른 수준의 페이지 테이블을 참조하도록 하는 방식이다. 32비트를 초과하는 주소 공간에서는 계층 수준이 매우 커질 수 있다. 이를 해결하는 두 가지 전략으로 해시 페이지 테이블과 역방향 페이지 테이블이 있다.
**11. Swapping allows the system to move pages belonging to a process to disk to increase the degree of multiprogramming.**

- 스와핑은 프로세스에 속한 페이지를 디스크로 옮겨 멀티프로그래밍 정도를 높일 수 있도록 해준다.
**12. The Intel 32-bit architecture has two levels of page tables and supports either 4-KB or 4-MB page sizes. This architecture also supports page-address extension, which allows 32-bit processors to access a physical address space larger than 4 GB. The x86-64 and ARMv9 architectures are 64-bit architectures that use hierarchical paging.**

- Intel 32비트 아키텍처는 2단계 페이지 테이블을 사용하며, 4KB 또는 4MB 크기의 페이지를 지원한다. 이 아키텍처는 32비트 프로세서가 4GB 이상의 물리 주소 공간에 접근할 수 있게 해주는 페이지-주소 확장 기능도 지원한다. x86-64와 ARMv9 아키텍처는 64비트 아키텍처로서, 계층적 페이징을 사용한다.

# 10강: Virtual Memory
**1. Virtual memory abstracts physical memory into an extremely large uniform array of storage.**

- 가상 메모리는 물리적 메모리를 매우 큰 균일한 저장소 배열로 추상화한다.
**2. The benefits of virtual memory include the following: (1) a program can be larger than physical memory, (2) a program does not need to be entirely in memory, (3) processes can share memory, and (4) processes can be created more efficiently.**

- 가상 메모리의 이점은 다음과 같다: (1) 프로그램의 크기가 물리적 메모리보다 클 수 있다, (2) 프로그램 전체가 메모리에 있을 필요가 없다, (3) 프로세스 간에 메모리를 공유할 수 있다, (4) 프로세스를 더 효율적으로 생성할 수 있다.
**3. Demand paging is a technique whereby pages are loaded only when they are demanded during program execution. Pages that are never demanded are thus never loaded into memory.**

- 요구 페이징은 프로그램 실행 중 필요한 페이지만 메모리에 로드하는 기술이다. 필요하지 않은 페이지는 메모리에 로드되지 않는다.
**4. A page fault occurs when a page that is currently not in memory is accessed. The page must be brought from the backing store into an available page frame in memory.**

- 페이지 폴트는 현재 메모리에 없는 페이지에 접근할 때 발생한다. 이 페이지는 백킹 스토어에서 메모리의 사용 가능한 페이지 프레임으로 불러와야 한다.
**5. Copy-on-write allows a child process to share the same address space as its parent. If either the child or the parent process writes (modifies) a page, a copy of the page is made.**

- Copy-on-write는 자식 프로세스가 부모 프로세스와 동일한 주소 공간을 공유하도록 한다. 자식 또는 부모 프로세스가 페이지를 수정하면 해당 페이지의 복사본이 생성된다.
**6. When available memory runs low, a page-replacement algorithm selects an existing page in memory to replace with a new page. Page-replacement algorithms include FIFO, optimal, and LRU. Pure LRU algorithms are impractical to implement, and most systems instead use LRU-approximation algorithms.**

- 사용 가능한 메모리가 부족할 때 페이지 교체 알고리즘이 메모리의 기존 페이지를 선택하여 새 페이지로 교체한다. 페이지 교체 알고리즘에는 FIFO, 최적(Optimal), LRU가 있다. 순수 LRU 알고리즘은 구현하기 어렵기 때문에 대부분의 시스템은 LRU 근사 알고리즘을 사용한다.
**7. Global page-replacement algorithms select a page from any process in the system for replacement, while local page-replacement algorithms select a page from the faulting process.**

- 글로벌 페이지 교체 알고리즘은 시스템의 모든 프로세스에서 페이지를 선택하지만, 로컬 페이지 교체 알고리즘은 폴트를 일으킨 프로세스에서만 페이지를 선택한다.
**8. Thrashing occurs when a system spends more time paging than executing.**

- 스래싱은 시스템이 실행하는 시간보다 페이징에 더 많은 시간을 소비할 때 발생한다.
**9. A locality represents a set of pages that are actively used together. As a process executes, it moves from locality to locality. A working set is based on locality and is defined as the set of pages currently in use by a process.**

- 지역성(locality)은 함께 자주 사용되는 페이지 집합을 나타낸다. 프로세스는 실행 중 여러 지역성으로 이동한다. 워킹 세트는 지역성을 기반으로 하며, 현재 프로세스에서 사용 중인 페이지 집합으로 정의된다.
**10. Memory compression is a memory-management technique that compresses a number of pages into a single page. Compressed memory is an alternative to paging and is used on mobile systems that do not support paging.**

- 메모리 압축은 여러 페이지를 하나의 페이지로 압축하는 메모리 관리 기법이다. 압축된 메모리는 페이징의 대안으로, 페이징을 지원하지 않는 모바일 시스템에서 사용된다.
**11. Kernel memory is allocated differently than user-mode processes; it is allocated in contiguous chunks of varying sizes. Two common techniques for allocating kernel memory are (1) the buddy system and (2) slab allocation.**

- 커널 메모리는 사용자 모드 프로세스와 다르게 할당되며, 다양한 크기의 연속된 청크로 할당된다. 커널 메모리 할당의 일반적인 두 가지 기법은 (1) 버디 시스템과 (2) 슬랩 할당이다.
**12. TLB reach refers to the amount of memory accessible from the TLB and is equal to the number of entries in the TLB multiplied by the page size. One technique for increasing TLB reach is to increase the size of pages.**

- TLB 도달 범위(TLB reach)는 TLB에서 접근할 수 있는 메모리 양을 의미하며, 이는 TLB의 엔트리 수와 페이지 크기의 곱과 같다. TLB 도달 범위를 늘리는 한 가지 방법은 페이지 크기를 늘리는 것이다.
**13. Linux, Windows, and Solaris manage virtual memory similarly, using demand paging and copy-on-write, among other features. Each system also uses a variation of LRU approximation known as the clock algorithm.**

- Linux, Windows, Solaris는 요구 페이징과 Copy-on-write를 포함한 기능들을 사용하여 가상 메모리를 유사하게 관리한다. 각 시스템은 또한 시계(clock) 알고리즘으로 알려진 LRU 근사 알고리즘의 변형을 사용한다.

# 11강: Mass Storage Structure
**1. Hard disk drives and nonvolatile memory devices are the major secondary storage I/O units on most computers. Modern secondary storage is structured as large one-dimensional arrays of logical blocks.**

- 하드 디스크 드라이브(HDD)와 비휘발성 메모리 장치는 대부분의 컴퓨터에서 주요한 2차 저장 장치 I/O 유닛이다. 현대의 2차 저장 장치는 논리 블록으로 구성된 큰 1차원 배열로 구조화된다.
**2. Drives of either type may be attached to a computer system in one of three ways: (1) through the local I/O ports on the host computer, (2) directly connected to motherboards, or (3) through a communications network or storage network connection.**

- 두 종류의 드라이브는 다음 세 가지 방법 중 하나로 컴퓨터 시스템에 연결될 수 있다: (1) 호스트 컴퓨터의 로컬 I/O 포트를 통해, (2) 메인보드에 직접 연결, (3) 통신 네트워크 또는 스토리지 네트워크를 통해 연결.
**3. Requests for secondary storage I/O are generated by the file system and by the virtual memory system. Each request specifies the address on the device to be referenced in the form of a logical block number.**

- 2차 저장 장치 I/O 요청은 파일 시스템과 가상 메모리 시스템에서 생성된다. 각 요청은 논리 블록 번호의 형태로 장치 내 참조할 주소를 지정한다.
**4. Disk-scheduling algorithms can improve the effective bandwidth of HDDs, the average response time, and the variance in response time. Algorithms such as SCAN and C-SCAN are designed to make such improvements through strategies for disk-queue ordering. Performance of disk-scheduling algorithms can vary greatly on hard disks. In contrast, because solid-state disks have no moving parts, performance varies little among scheduling algorithms, and quite often a simple FCFS strategy is used.**

- 디스크 스케줄링 알고리즘은 HDD의 유효 대역폭, 평균 응답 시간 및 응답 시간의 변동성을 개선할 수 있다. SCAN 및 C-SCAN과 같은 알고리즘은 디스크 큐 정렬 전략을 통해 이러한 개선을 목표로 설계되었다. 하드 디스크에서는 디스크 스케줄링 알고리즘의 성능 차이가 클 수 있지만, SSD는 움직이는 부품이 없으므로 알고리즘에 따른 성능 차이가 거의 없으며 종종 단순한 FCFS 전략이 사용된다.
**5. Data storage and transmission are complex and frequently result in errors. Error detection attempts to spot such problems to alert the system for corrective action and to avoid error propagation. Error correction can detect and repair problems, depending on the amount of correction data available and the amount of data that was corrupted.**

- 데이터 저장 및 전송은 복잡하며 종종 오류를 유발한다. 오류 감지는 문제를 찾아내어 시스템에 알림으로써 수정 조치를 취하고 오류 확산을 방지한다. 오류 수정은 사용 가능한 수정 데이터의 양과 손상된 데이터의 양에 따라 문제를 감지하고 복구할 수 있다.
**6. Storage devices are partitioned into one or more chunks of space. Each partition can hold a volume or be part of a multidevice volume. File systems are created in volumes.**

- 저장 장치는 하나 이상의 공간 덩어리로 분할된다. 각 파티션은 하나의 볼륨을 포함하거나 다중 장치 볼륨의 일부가 될 수 있다. 파일 시스템은 볼륨에 생성된다.
**7. The operating system manages the storage device’s blocks. New devices typically come pre-formatted. The device is partitioned, file systems are created, and boot blocks are allocated to store the system’s bootstrap program if the device will contain an operating system. Finally, when a block or page is corrupted, the system must have a way to lock out that block or to replace it logically with a spare.**

- 운영체제는 저장 장치의 블록을 관리한다. 새 장치는 일반적으로 사전 포맷되어 제공된다. 장치는 파티션화되고, 파일 시스템이 생성되며, 운영체제를 포함하는 장치의 경우 부트 블록이 시스템의 부트스트랩 프로그램을 저장하도록 할당된다. 마지막으로 블록이나 페이지가 손상되면, 시스템은 해당 블록을 비활성화하거나 예비 블록으로 논리적으로 교체하는 방법을 제공해야 한다.
**8. An efficient swap space is a key to good performance in some systems. Some systems dedicate a raw partition to swap space, and others use a file within the file system instead. Still other systems allow the user or system administrator to make the decision by providing both options.**

- 효율적인 스왑 공간은 일부 시스템에서 성능의 핵심이다. 일부 시스템은 스왑 공간에 원시(raw) 파티션을 할당하고, 다른 시스템은 파일 시스템 내 파일을 사용한다. 일부 시스템은 사용자나 시스템 관리자가 두 옵션 중 하나를 선택할 수 있도록 한다.
**9. Because of the amount of storage required on large systems, and because storage devices fail in various ways, secondary storage devices are frequently made redundant via RAID algorithms. These algorithms allow more than one drive to be used for a given operation and allow continued operation and even automatic recovery in the face of a drive failure. RAID algorithms are organized into different levels; each level provides some combination of reliability and high transfer rates.**

- 대형 시스템에서 요구되는 저장 용량과 저장 장치의 다양한 고장 가능성 때문에, 2차 저장 장치는 종종 RAID 알고리즘을 통해 중복화된다. 이러한 알고리즘은 여러 드라이브를 하나의 작업에 사용할 수 있게 하고, 드라이브 고장 시에도 지속적인 운영 및 자동 복구를 가능하게 한다. RAID 알고리즘은 여러 레벨로 구성되며, 각 레벨은 신뢰성과 높은 전송률의 조합을 제공한다.
**10. Object storage is used for big data problems such as indexing the Internet and cloud photo storage. Objects are self-defining collections of data, addressed by object ID rather than file name. Typically it uses replication for data protection, computes based on the data on systems where a copy of the data exists, and is horizontally scalable for vast capacity and easy expansion.**

- 객체 스토리지는 인터넷 색인화 및 클라우드 사진 저장과 같은 빅 데이터 문제에 사용된다. 객체는 파일 이름이 아닌 객체 ID로 주소화되는 자가 정의 데이터 컬렉션이다. 일반적으로 데이터 보호를 위해 복제를 사용하고, 데이터 사본이 존재하는 시스템에서 데이터를 기반으로 계산하며, 방대한 용량과 손쉬운 확장을 위해 수평적으로 확장 가능하다.
***

# 12강: I/O Systems
**1. The basic hardware elements involved in I/O are buses, device controllers, and the devices themselves.**

- I/O에 관련된 기본 하드웨어 요소는 버스, 장치 컨트롤러, 그리고 장치 자체이다.
**2. The work of moving data between devices and main memory is performed by the CPU as programmed I/O or is offloaded to a DMA controller.**

- 장치와 주 메모리 간의 데이터 이동 작업은 프로그래밍된 I/O로 CPU가 수행하거나 DMA 컨트롤러로 오프로드된다.
**3. The kernel module that controls a device is a device driver. The system-call interface provided to applications is designed to handle several basic categories of hardware, including block devices, character-stream devices, memory-mapped files, network sockets, and programmed interval timers.**

- 장치를 제어하는 커널 모듈은 장치 드라이버이다. 애플리케이션에 제공되는 시스템 콜 인터페이스는 블록 장치, 문자 스트림 장치, 메모리 매핑 파일, 네트워크 소켓, 그리고 프로그래밍된 간격 타이머를 포함한 여러 하드웨어 카테고리를 처리하도록 설계되었다.
**4. The system calls usually block the processes that issue them, but non-blocking and asynchronous calls are used by the kernel itself and by applications that must not sleep while waiting for an I/O operation to complete.**

- 시스템 콜은 보통 이를 호출한 프로세스를 블록하지만, 커널 자체와 I/O 작업이 완료될 때까지 대기할 수 없는 애플리케이션은 논블로킹 및 비동기 호출을 사용한다.
**5. The kernel’s I/O subsystem provides numerous services. Among these are I/O scheduling, buffering, caching, spooling, device reservation, error handling.**

- 커널의 I/O 서브시스템은 I/O 스케줄링, 버퍼링, 캐싱, 스풀링, 장치 예약, 오류 처리를 포함한 여러 서비스를 제공한다.
**6. Another service, name translation, makes the connections between hardware devices and the symbolic file names used by applications. It involves several levels of mapping that translate from character-string names, to specific device drivers and device addresses, and then to physical addresses of I/O ports or bus controllers.**

- 다른 서비스인 이름 변환은 하드웨어 장치와 애플리케이션에서 사용하는 심볼릭 파일 이름 간의 연결을 수행한다. 이 과정은 문자 문자열 이름에서 특정 장치 드라이버와 장치 주소로, 그리고 물리적 I/O 포트나 버스 컨트롤러의 주소로 변환하는 여러 수준의 매핑을 포함한다.
**7. This mapping may occur within the file-system name space, as it does in UNIX, or in a separate device name space, as it does in MS-DOS.**

- 이 매핑은 UNIX와 같이 파일 시스템 이름 공간 내에서 발생하거나 MS-DOS와 같이 별도의 장치 이름 공간에서 발생할 수 있다.
**8. STREAMS is an implementation and methodology that provides a framework for a modular and incremental approach to writing device drivers and network protocols.**

- STREAMS는 장치 드라이버와 네트워크 프로토콜을 작성하는 모듈식 및 점진적 접근 방식을 위한 프레임워크를 제공하는 구현 및 방법론이다.
**9. Through STREAMS, drivers can be stacked, with data passing through them sequentially and bidirectionally for processing.**

- STREAMS를 통해 드라이버는 스택으로 쌓을 수 있으며, 데이터는 이를 통해 순차적이고 양방향으로 전달되며 처리된다.
**10. I/O system calls are costly in terms of CPU consumption because of the many layers of software between a physical device and an application.**

- I/O 시스템 콜은 물리적 장치와 애플리케이션 사이에 많은 소프트웨어 계층이 존재하므로 CPU 소모 측면에서 비용이 많이 든다.
**11. These layers imply overhead from several sources: context switching to cross the kernel’s protection boundary, signal and interrupt handling to service the I/O devices, and the load on the CPU and memory system to copy data between kernel buffers and application space.**

- 이러한 계층은 여러 출처로부터 오버헤드를 초래한다: 커널 보호 경계를 넘기 위한 컨텍스트 전환, I/O 장치를 서비스하기 위한 신호 및 인터럽트 처리, 커널 버퍼와 애플리케이션 공간 간의 데이터를 복사하기 위한 CPU와 메모리 시스템의 부하.
***

# 13강: 파일 시스템 인터페이스
**1. A file is an abstract data type defined and implemented by the operating system. It is a sequence of logical records. A logical record may be a byte, a line (of fixed or variable length), or a more complex data item. The operating system may specifically support various record types or may leave that support to the application program.**

- 파일은 운영체제에 의해 정의되고 구현된 추상 데이터 타입이다. 파일은 논리적 레코드의 순서로 구성된다. 논리적 레코드는 바이트, 고정 또는 가변 길이의 줄, 혹은 더 복잡한 데이터 항목일 수 있다. 운영체제는 다양한 레코드 타입을 구체적으로 지원하거나 그 지원을 애플리케이션 프로그램에 맡길 수 있다.
**2. A major task for the operating system is to map the logical file concept onto physical storage devices such as hard disk or NVM device. Since the physical record size of the device may not be the same as the logical record size, it may be necessary to order logical records into physical records. Again, this task may be supported by the operating system or left for the application program.**

- 운영체제의 주요 작업 중 하나는 논리적 파일 개념을 하드 디스크나 비휘발성 메모리 장치(NVM)와 같은 물리적 저장 장치에 매핑하는 것이다. 물리적 레코드 크기가 논리적 레코드 크기와 다를 수 있으므로, 논리적 레코드를 물리적 레코드로 정렬하는 과정이 필요할 수 있다. 이 작업은 운영체제에서 지원하거나 애플리케이션 프로그램에 맡길 수 있다.
**3. Within a file system, it is useful to create directories to allow files to be organized. A single-level directory in a multiuser system causes naming problems, since each file must have a unique name. A two-level directory solves this problem by creating a separate directory for each user’s files. The directory lists the files by name and includes the file’s location on the disk, length, type, owner, time of creation, time of last use, and so on.**

- 파일 시스템 내에서 파일을 체계적으로 관리하기 위해 디렉터리를 생성하는 것이 유용하다. 다중 사용자 시스템에서 단일 레벨 디렉터리는 모든 파일이 고유한 이름을 가져야 하기 때문에 명명 문제가 발생한다. 2단계 디렉터리는 각 사용자의 파일을 위한 별도의 디렉터리를 생성함으로써 이 문제를 해결한다. 디렉터리는 파일 이름, 디스크 상의 위치, 길이, 타입, 소유자, 생성 시간, 마지막 사용 시간 등을 포함한다.
**4. The natural generalization of a two-level directory is a tree-structured directory. A tree-structured directory allows a user to create subdirectories to organize files. Acyclic-graph directory structures enable users to share subdirectories and files but complicate searching and deletion. A general graph structure allows complete flexibility in the sharing of files and directories but sometimes requires garbage collection to recover unused disk space.**

- 2단계 디렉터리의 자연스러운 확장은 트리 구조 디렉터리이다. 트리 구조 디렉터리는 사용자가 파일을 관리하기 위해 하위 디렉터리를 생성할 수 있게 한다. 비순환 그래프 디렉터리 구조는 하위 디렉터리와 파일의 공유를 가능하게 하지만, 검색과 삭제를 복잡하게 만든다. 일반적인 그래프 구조는 파일과 디렉터리의 공유에 완전한 유연성을 제공하지만, 때때로 사용되지 않는 디스크 공간을 회수하기 위해 가비지 컬렉션이 필요하다.
**5. Remote file systems present challenges in reliability, performance, and security. Distributed information systems maintain user, host, and access information so that clients and servers can share state information to manage use and access.**

- 원격 파일 시스템은 신뢰성, 성능, 보안 측면에서 어려움을 제공한다. 분산 정보 시스템은 사용자, 호스트 및 접근 정보를 유지하여 클라이언트와 서버가 상태 정보를 공유하고 사용 및 접근을 관리할 수 있도록 한다.
**6. Since files are the main information-storage mechanism in most computer systems, file protection is needed on multiuser systems. Access to files can be controlled separately for each type of access—read, write, execute, append, delete, list directory, and so on. File protection can be provided by access lists, passwords, or other techniques.**

- 파일은 대부분의 컴퓨터 시스템에서 주요 정보 저장 메커니즘이므로 다중 사용자 시스템에서는 파일 보호가 필요하다. 파일 접근은 읽기, 쓰기, 실행, 추가, 삭제, 디렉터리 목록화 등 각 접근 유형에 따라 개별적으로 제어될 수 있다. 파일 보호는 접근 제어 리스트, 비밀번호 또는 기타 기법을 통해 제공될 수 있다.
***

# 14강 파일 시스템 구현
**1. Most file systems reside on secondary storage, which is designed to hold a large amount of data permanently. The most common secondary-storage medium is the disk, but the use of NVM devices is increasing.**

- 대부분의 파일 시스템은 대량의 데이터를 영구적으로 저장하도록 설계된 2차 저장 장치에 존재한다. 가장 일반적인 2차 저장 매체는 디스크이지만, 비휘발성 메모리(NVM) 장치의 사용이 증가하고 있다.
**2. Storage devices are segmented into partitions to control media use and to allow multiple, possibly varying, file systems on a single device. These file systems are mounted onto a logical file system architecture to make them available for use.**

- 저장 장치는 미디어 사용을 제어하고 단일 장치에서 여러 파일 시스템(서로 다른 파일 시스템 포함)을 허용하기 위해 파티션으로 나뉜다. 이러한 파일 시스템은 논리적 파일 시스템 아키텍처에 마운트되어 사용 가능하게 된다.
**3. File systems are often implemented in a layered or modular structure. The lower levels deal with the physical properties of storage devices and communicating with them. Upper levels deal with symbolic file names and logical properties of files.**

- 파일 시스템은 종종 계층적 또는 모듈식 구조로 구현된다. 하위 계층은 저장 장치의 물리적 특성과의 통신을 처리하고, 상위 계층은 심볼릭 파일 이름과 파일의 논리적 특성을 처리한다.
**4. The various files within a file system can be allocated space on the storage device in three ways: through contiguous, linked, or indexed allocation.**

- 파일 시스템의 여러 파일은 저장 장치에서 연속 할당, 연결 할당, 또는 인덱스 할당의 세 가지 방법으로 공간을 할당받을 수 있다.
**5. Contiguous allocation can suffer from external fragmentation. Direct access is very inefficient with linked allocation. Indexed allocation may require substantial overhead for its index block.**

- 연속 할당은 외부 단편화의 문제가 발생할 수 있다. 연결 할당은 직접 접근에서 매우 비효율적이다. 인덱스 할당은 인덱스 블록 때문에 상당한 오버헤드를 요구할 수 있다.
**6. These algorithms can be optimized in many ways. Contiguous space can be enlarged through extents to increase flexibility and to decrease external fragmentation.**

- 이러한 알고리즘은 다양한 방법으로 최적화될 수 있다. 연속 공간은 익스텐트(extents)를 통해 확장되어 유연성을 높이고 외부 단편화를 줄일 수 있다.
**7. Indexed allocation can be done in clusters of multiple blocks to increase throughput and to reduce the number of index entries needed. Indexing in large clusters is similar to contiguous allocation with extents.**

- 인덱스 할당은 여러 블록의 클러스터 단위로 수행되어 처리량을 늘리고 필요한 인덱스 항목 수를 줄일 수 있다. 대형 클러스터에서의 인덱싱은 익스텐트를 사용하는 연속 할당과 유사하다.
**8. Free-space allocation methods also influence the efficiency of disk-space use, the performance of the file system, and the reliability of secondary storage. The methods used include bit vectors and linked lists.**

- 여유 공간 할당 방법은 디스크 공간 사용의 효율성, 파일 시스템의 성능, 그리고 2차 저장 장치의 신뢰성에 영향을 미친다. 사용되는 방법에는 비트 벡터와 연결 리스트가 있다.
**9. Optimizations include grouping, counting, and the FAT, which places the linked list in one contiguous area.**

- 최적화에는 그룹화, 카운팅, 그리고 FAT(파일 할당 테이블)가 있으며, FAT는 연결 리스트를 하나의 연속된 영역에 배치한다.
**10. Directory-management routines must consider efficiency, performance, and reliability. A hash table is a commonly used method, as it is fast and efficient.**

- 디렉터리 관리 루틴은 효율성, 성능, 신뢰성을 고려해야 한다. 해시 테이블은 빠르고 효율적이기 때문에 일반적으로 사용되는 방법이다.
**11. Unfortunately, damage to the table or a system crash can result in inconsistency between the directory information and the disk’s contents.**

- 하지만 테이블 손상이나 시스템 충돌이 발생하면 디렉터리 정보와 디스크 내용 사이에 불일치가 생길 수 있다.
**12. A consistency checker can be used to repair damaged file-system structures. Operating-system backup tools allow data to be copied to magnetic tape or other storage devices, enabling the user to recover from data loss or even entire device loss due to hardware failure, operating system bug, or user error.**

- 일관성 검사기(consistency checker)는 손상된 파일 시스템 구조를 복구하는 데 사용될 수 있다. 운영체제의 백업 도구는 데이터를 자기 테이프 또는 다른 저장 장치에 복사하여 하드웨어 오류, 운영체제 버그, 사용자 실수로 인한 데이터 손실이나 전체 장치 손실에서 복구할 수 있도록 해준다.
**13. Due to the fundamental role that file systems play in system operation, their performance and reliability are crucial. Techniques such as log structures and caching help improve performance, while log structures and RAID improve reliability.**

- 파일 시스템은 시스템 운영에서 근본적인 역할을 하기 때문에 성능과 신뢰성이 매우 중요하다. 로그 구조와 캐싱 같은 기술은 성능을 개선하고, 로그 구조와 RAID는 신뢰성을 향상시킨다.
**14. The WAFL file system is an example of optimization of performance to match a specific I/O load.**

- WAFL 파일 시스템은 특정 I/O 부하에 맞게 성능을 최적화한 예시이다.

# 15강: 파일 시스템 내부
**1. General-purpose operating systems provide many file-system types, from special-purpose through general.**

- 범용 운영체제는 특수 목적부터 범용까지 다양한 파일 시스템 유형을 제공한다.
**2. Volumes containing file systems can be mounted into the computer’s file-system space.**

- 파일 시스템을 포함한 볼륨은 컴퓨터의 파일 시스템 공간에 마운트될 수 있다.
**3. Depending on the operating system, the file-system space is seamless (mounted file systems integrated into the directory structure) or distinct (each mounted file system having its own designation).**

- 운영체제에 따라 파일 시스템 공간은 매끄럽게 통합될 수 있으며(마운트된 파일 시스템이 디렉터리 구조에 통합됨), 혹은 별개일 수 있다(각 마운트된 파일 시스템이 고유한 명칭을 가짐).
**4. At least one file system must be bootable for the system to be able to start — that is, it must contain an operating system. The boot loader is run first; it is a simple program that is able to find the kernel in the file system, load it, and start its execution. Systems can contain multiple bootable partitions, letting the administrator choose which to run at boot time.**

- 시스템이 시작되기 위해서는 적어도 하나의 부팅 가능한 파일 시스템이 필요하며, 이 파일 시스템은 운영체제를 포함해야 한다. 부트 로더가 먼저 실행되며, 부트 로더는 파일 시스템에서 커널을 찾아 로드하고 실행하는 간단한 프로그램이다. 시스템은 여러 부팅 가능한 파티션을 포함할 수 있으며, 관리자가 부팅 시 실행할 파티션을 선택할 수 있다.
**5. Most systems are multi-user and thus must provide a method for file sharing and file protection. Frequently, files and directories include metadata, such as owner, user, and group access permissions.**

- 대부분의 시스템은 다중 사용자 시스템이므로 파일 공유와 파일 보호 방법을 제공해야 한다. 일반적으로 파일과 디렉터리는 소유자, 사용자, 그룹 접근 권한과 같은 메타데이터를 포함한다.
**6. Mass storage partitions are used either for raw block I/O or for file systems. Each file system resides in a volume, which can be composed of one partition or multiple partitions working together via a volume manager.**

- 대용량 저장소 파티션은 원시 블록 I/O 또는 파일 시스템을 위해 사용된다. 각 파일 시스템은 하나의 볼륨에 존재하며, 이 볼륨은 하나의 파티션이나 볼륨 관리자를 통해 여러 파티션이 함께 작동하여 구성될 수 있다.
**7. To simplify implementation of multiple file systems, an operating system can use a layered approach, with a virtual file-system interface making access to possibly dissimilar file systems seamless.**

- 여러 파일 시스템의 구현을 단순화하기 위해 운영체제는 계층적 접근 방식을 사용할 수 있으며, 가상 파일 시스템 인터페이스를 통해 서로 다른 파일 시스템에 대한 접근을 매끄럽게 처리한다.
**8. Remote file systems can be implemented simply by using a program such as ftp or the web servers and clients in the World Wide Web, or with more functionality via a client–server model. Mount requests and user IDs must be authenticated to prevent unapproved access.**

- 원격 파일 시스템은 ftp와 같은 프로그램이나 월드 와이드 웹의 웹 서버와 클라이언트를 사용하여 간단히 구현되거나, 클라이언트-서버 모델을 통해 더 많은 기능을 제공할 수 있다. 마운트 요청과 사용자 ID는 비인가 접근을 방지하기 위해 인증되어야 한다.
**9. Client–server facilities do not natively share information, but a distributed information system such as DNS can be used to allow such sharing, providing a unified user name space, password management, and system identification.**

- 클라이언트-서버 기능은 기본적으로 정보를 공유하지 않지만, DNS와 같은 분산 정보 시스템을 사용하면 공유를 허용하고, 통합된 사용자 이름 공간, 비밀번호 관리 및 시스템 식별을 제공할 수 있다.
**10. For example, Microsoft CIFS uses active directory, which employs a version of the Kerberos network authentication protocol to provide a full set of naming and authentication services among the computers in a network.**

- 예를 들어, Microsoft CIFS는 액티브 디렉터리를 사용하며, 이는 Kerberos 네트워크 인증 프로토콜의 버전을 사용하여 네트워크 내 컴퓨터 간의 완전한 명명 및 인증 서비스를 제공한다.
**11. Once file sharing is possible, a consistency semantics model must be chosen and implemented to moderate multiple concurrent access to the same file. Semantics models include UNIX, session, and immutable-shared-files semantics.**

- 파일 공유가 가능해지면 동일 파일에 대한 다중 동시 접근을 조정하기 위해 일관성 의미론 모델이 선택되고 구현되어야 한다. 의미론 모델에는 UNIX, 세션, 불변 공유 파일 의미론이 포함된다.
**12. NFS is an example of a remote file system, providing clients with seamless access to directories, files, and even entire file systems. A full-featured remote file system includes a communication protocol with remote operations and path-name translation.**

- NFS는 원격 파일 시스템의 예로, 클라이언트에게 디렉터리, 파일, 심지어 전체 파일 시스템에 대한 매끄러운 접근을 제공한다. 완전한 기능의 원격 파일 시스템은 원격 작업과 경로 이름 변환을 포함하는 통신 프로토콜을 제공한다.

# 16강 보안
**1. Protection is an internal problem. Security, in contrast, must consider both the computer system and the environment—people, buildings, businesses, valuable objects, and threats—within which the system is used.**

- 보호는 내부적인 문제이다. 반면, 보안은 컴퓨터 시스템뿐만 아니라 시스템이 사용되는 환경(사람, 건물, 사업체, 가치 있는 객체, 위협)을 모두 고려해야 한다.
**2. The data stored in the computer system must be protected from unauthorized access, malicious destruction or alteration, and accidental introduction of inconsistency. It is easier to protect against accidental loss of data consistency than to protect against malicious access to the data.**

- 컴퓨터 시스템에 저장된 데이터는 무단 접근, 악의적인 파괴나 변경, 우연한 불일치 도입으로부터 보호되어야 한다. 데이터 일관성의 우연한 손실을 방지하는 것이 악의적인 접근으로부터 데이터를 보호하는 것보다 쉽다.
**3. Absolute protection of the information stored in a computer system from malicious abuse is not possible; but the cost to the perpetrator can be made sufficiently high to deter most, if not all, attempts to access that information without proper authority.**

- 컴퓨터 시스템에 저장된 정보를 악의적으로 남용하는 것을 완전히 방지하는 것은 불가능하지만, 공격자가 정보를 무단으로 접근하는 데 드는 비용을 충분히 높여 대부분의 시도를 억제할 수 있다.
**4. Several types of attacks can be launched against programs and against individual computers or the masses. Stack- and buffer-overflow techniques allow successful attackers to change their level of system access.**

- 여러 종류의 공격이 프로그램, 개별 컴퓨터 또는 대규모 시스템에 대해 수행될 수 있다. 스택 및 버퍼 오버플로 기법을 사용하면 공격자가 시스템 접근 수준을 변경할 수 있다.
**5. Viruses and malware require human interaction, while worms are self-perpetuating, sometimes infecting thousands of computers. Denial-of-service attacks prevent legitimate use of target systems.**

- 바이러스와 악성 소프트웨어는 인간의 개입을 필요로 하지만, 웜은 자체적으로 확산되며 때로는 수천 대의 컴퓨터를 감염시킨다. 서비스 거부(DoS) 공격은 대상 시스템의 정당한 사용을 방해한다.
**6. Encryption limits the domain of receivers of data, while authentication limits the domain of senders. Encryption is used to provide confidentiality of data being stored or transferred.**

- 암호화는 데이터 수신자의 범위를 제한하고, 인증은 데이터 송신자의 범위를 제한한다. 암호화는 저장되거나 전송되는 데이터의 기밀성을 제공하는 데 사용된다.
**7. Symmetric encryption requires a shared key, while asymmetric encryption provides a public key and a private key. Authentication, when combined with hashing, can prove that data have not been changed.**

- 대칭 암호화는 공유 키를 필요로 하지만, 비대칭 암호화는 공개 키와 개인 키를 제공한다. 인증은 해싱과 결합될 때 데이터가 변경되지 않았음을 증명할 수 있다.
**8. User authentication methods are used to identify legitimate users of a system. In addition to standard user-name and password protection, several authentication methods are used.**

- 사용자 인증 방법은 시스템의 정당한 사용자를 식별하는 데 사용된다. 표준 사용자 이름과 비밀번호 보호 외에도 다양한 인증 방법이 사용된다.
**9. One-time passwords, for example, change from session to session to avoid replay attacks. Two-factor authentication requires two forms of authentication, such as a hardware calculator with an activation PIN, or one that presents a different response based on the time.**

- 예를 들어, 일회용 비밀번호는 세션마다 변경되어 재전송 공격을 방지한다. 이중 인증은 활성화 PIN이 있는 하드웨어 계산기나 시간에 따라 다른 응답을 제공하는 형태와 같은 두 가지 인증 방법을 요구한다.
**10. Multifactor authentication uses three or more forms. These methods greatly decrease the chance of authentication forgery.**

- 다중 인증은 세 가지 이상의 인증 방식을 사용한다. 이러한 방법은 인증 위조의 가능성을 크게 줄여준다.
**11. Methods of preventing or detecting security incidents include an up-to-date security policy, intrusion-detection systems, antivirus software, auditing and logging of system events, system-call monitoring, code signing, sandboxing, and firewalls.**

- 보안 사고를 예방하거나 감지하는 방법에는 최신 보안 정책, 침입 탐지 시스템, 안티바이러스 소프트웨어, 시스템 이벤트 감사 및 로깅, 시스템 콜 모니터링, 코드 서명, 샌드박싱, 그리고 방화벽이 있다.
